# ADR-0006 — RNG: ChaCha8 with keyed per-(subsystem, entity, tick, purpose) streams

Status: Proposed · Date: 2026-11-22 · Workstream: WS-02 · Supports: SYS-002, P-4

## Context
M1 research: the Rand book recommends `ChaCha8Rng` for portable reproducibility and allows value-breaking changes in minor versions [V: m1-findings §5]. Draws must not depend on how many draws other subsystems or polities made, or adding content and reordering code would change every outcome.

## Options
| Option | For | Against |
|---|---|---|
| One global stream | Simplest | Any extra draw anywhere shifts everything after it; no parallelism |
| One stream per subsystem/polity, persisted across ticks | Isolation between subsystems | Stream position becomes save state; a draw-count change in one tick shifts all later ticks of that stream |
| `ChaCha8Rng::set_stream` with a packed u64 | No hashing | Only 64 bits of key; still needs word-position bookkeeping per tick |
| **Fresh stream per (seed, tag, entity, tick, purpose) via `blake3::derive_key`** | Total isolation; nothing to save; parallel-safe; content keyed by string ID so additions don't perturb existing truth | 288 ns per stream [V: measured]; must forbid reusing a key within a tick |

## Decision
`ChaCha8Rng::from_seed(blake3::derive_key("orchestra rng v1", seed ‖ tag ‖ entity ‖ tick ‖ purpose))`, with world truth keyed by content string ID instead of tick. Pins: `rand_core =0.10.1`, `rand_chacha =0.10.0`, `rand =0.10.4`, `rand_distr =0.6.0` [V: compiled together 2026-11-22], `blake3` 1.8.x. Golden-value test `arc_031_rng_golden` with values measured on 2026-11-22 (spec ARC-031).

## Consequences
- Upgrading any RNG crate is a deliberate change: update the golden values, bump the save format version, and note it in the change log.
- Changing the derivation context string (`v1`) changes every world; do it only with a version bump.
- Determinism is guaranteed per target triple and build only (OQ-A1 closed 2026-11-25: cross-platform not required). Integer and uniform-`f64` golden values are platform-independent; values from samplers that use `exp`/`ln` are exact on Linux CI and checked to 1e-12 relative on Windows.
