# WS-02 — Architecture & Data Model · Phase A kickoff

```
Workstream WS-02 — Architecture & Data Model for Orchestra (repo AbscissaOrdinate/Orchestra).

Read first: docs/conops.md (§5 principles, §7, §9 SYS-), docs/adr/0001–0003, docs/research/m1-findings.md §5, docs/specs/README.md.

Objective: produce docs/specs/WS-02-architecture.md with ARC- requirements, plus any new ADRs. This spec defines the skeleton every other workstream plugs into, so it must be done before WS-03 to WS-05 are implemented (milestone M4).

Scope (MVP):
- Cargo workspace: crates/sim-core (headless), crates/cli, app/ (Tauri, stub only)
- World state model: polities (generic type, with fidelity tier as a field), regions (graph), Solar System bodies (graph), world truth vs. per-polity beliefs (P-1, P-2)
- Tick pipeline: a fixed, ordered sequence of subsystem phases each month (Decide → Resolve → Inform); how subsystems register; how they read and write state without depending on ordering hazards
- RNG: ChaCha8Rng with deterministic per-subsystem and per-polity substreams derived from the world seed (SYS-002, P-4). Pin versions and add a golden-value test.
- Explainability: a breakdown type (value = Σ labeled terms) that every state update produces, and the query API (SYS-004, P-3)
- Content loading: RON schemas as Rust types, validated at load, with setting/map separation (SYS-007, ADR-0001, ADR-0003)
- Save/load and replay: state snapshot plus input log; state hash (SYS-002)
- CLI: run, batch Monte Carlo with summary stats, export to JSON (SYS-003)
- Fidelity tiers: interface for macro vs. high-fidelity polities, and conservation on tier switch (SYS-006)
- Performance budget: SYS-008

Out of scope: any subsystem's model equations (WS-03 to WS-08); UI beyond a Tauri hello-world that calls sim-core.

Decisions to make:
1. ECS (e.g., bevy_ecs headless) vs. plain structs-of-vectors. Lazy-first: justify any dependency.
2. Breakdown representation and its memory cost (keep every tick? last N? on-demand recompute?)
3. Belief representation: (mean, σ) per scalar, or something richer for multimodal techs
4. Phase ordering and double-buffering (read old state, write new) vs. in-place updates
5. Save format (RON? bincode?) and versioning

Working method: options → trade-offs → recommendation; at most 5 questions; tag values [V]/[R]/[D].
Deliverables: spec + ADRs on a branch with a PR; POAM updated (M1/M3 status).
Done when: every ARC- requirement is testable, and WS-03 to WS-05 could start coding against the interfaces defined here.
```
